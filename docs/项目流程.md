## 一、完成定义（DoD）

项目视为「完成」需同时满足：

1. `python -m app` 启动后出现桌面窗口，点「开始捕获」后 `./cache/screenshots/` 持续产生 jpeg。
2. 浏览器打开 `http://127.0.0.1:<port>`，无需刷新即可看到最新截图（WebSocket 推送）。
3. 裁剪框只影响 web 端显示，桌面端与落盘文件始终是全尺寸原图。
4. 关窗进托盘且捕获不中断；托盘右键可切换捕获状态并退出。
5. 打包出的 exe 在无 Python 环境的机器上可运行。

### P1 捕获内核（先无 UI）

用 `windows-capture` 的 `WindowsCapture` 类，构造参数按目标二选一：

- 显示器：`monitor_index=N` —— **N 从 1 开始**（1 = 主显示器；传 0 会在启动瞬间报
  `Failed to get monitor from index: The monitor index must be greater than zero.`）
- 窗口：`window_name="..."` 或 `window_hwnd=...`（hwnd 更可靠，同名窗口会歧义；
  构造参数里两者与 `monitor_index` 互斥，给窗口目标时库会自己清掉 monitor_index）

关键点：

- 回调走 `@event`（即 `frame_handler`）；`start_free_threaded()` 在专用线程启动，不要在主线程阻塞。
- 回调参数是 `NativeMappedFrame`，转 numpy 后拿到的 `Frame.frame_buffer` 是**零拷贝视图**，`Frame.crop()` 返回的是 numpy 切片视图 —— **必须在回调内立刻转 JPEG 落盘或 `.copy()`**，绝不能在回调之外持有缓冲区引用，否则会出现半张图/撕裂。
- 存 jpeg 直接用 `Frame.save_as_image(path)`（内部 `cv2.imwrite`）；要控质量则自己调 `cv2.imwrite(path, bgr, [cv2.IMWRITE_JPEG_QUALITY, q])`，注意先 `convert_to_bgr()`。
- 间隔调度：用 `minimum_update_interval` 只能做节流，真正的「每 N 秒存一张」应由自己的定时器控制，避免高频回调写盘。
- `storage.py` 实现 20 + 1：按时间排序删除最旧，但**被 web 端正在预览的那张要钉住跳过**。
- 切换捕获目标（换窗口/换屏）：停旧实例 → 建新实例，不要复用。

**验收**：命令行模式下让引擎裸跑 30 秒以上，`cache/screenshots/` 中的 jpeg 数量稳定在 ≤21 且文件名递增、能被图片查看器正常打开；换成窗口捕获后画面内容确实变成该窗口。
对应进度条目：1.1 全部（裁剪项除外）。

实测结论：

- 35 秒 / 间隔 2 秒：回调 336 帧 → 只落盘 17 张，相邻实际间隔 2.01–2.19 秒，全部 1920x1080 jpeg
  （间隔门有效，不是「每帧存一张」）；
- 缓存上限现场改成 5 后跑 20 秒：磁盘最终恰好 5 张，日志逐条记录删除的最旧文件；
- 窗口捕获：按标题捕获纯品红测试窗口，落盘图为该窗口（品红占比 88.6%），不是整个桌面；
- **静止屏幕不出帧**是 WGC 的固有行为，自检用 `--jiggle`（光标来回 1 像素）制造画面变化来驱动。
  P2/P3 阶段发现这在真实使用中是不可接受的：捕获一个静止窗口，15 秒只落盘 1 张，缓存不轮转、
  预览不刷新。解决方案是引擎内的**静止兜底心跳**（见 P2 实测记录）：

  - 窗口：`PrintWindow(PW_RENDERFULLCONTENT)`；只配了标题时先解析成 hwnd；
  - 显示器：`CreateDC("DISPLAY")` 的桌面 DC 按显示器矩形 `BitBlt`（**不要**用
    `GetWindowDC(GetDesktopWindow())`，它会让 BitBlt 失败）；
  - 距上次**落盘**超过一个间隔就抓一帧，同时喂预览与落盘；配置项 `capture.heartbeat_fallback`。
    （判据**只看落盘**，别看「距上次收到帧」：画面轻微活动时 WGC 出帧频率远高于落盘间隔，
    那样写会把心跳永远推迟，实测间隔漂到 4 秒；「一个间隔一张」由 `_save_image` 锁内占位保证。）

### P2 桌面端主界面

- 实时预览 + 下边栏（开始/停止、捕获范围、范围选择）。

**验收**：点开始/停止，预览与状态指示同步变化；改间隔为 2 秒后落盘频率确实变化。

### P3 捕获范围与目标选择

- 「捕获范围」弹窗：窗口选择栏（枚举顶层窗口，排除自身、无标题、不可见、DWM 幽灵窗口）＋屏幕选择栏，

  屏幕选择栏**不能**直接用 `QGuiApplication.screens()` 的顺序：实测本机上 Qt 把主显示器排在第一位，
  而捕获库的 `monitor_index` 顺序是 `EnumDisplayMonitors` 的顺序，两者不一致。
- 窗口枚举：`windows-capture` 2.0.1 **不提供**窗口/显示器枚举 API（已核对 wheel 内的 `__init__.py`，无 `find_window` / `window_names` / `Monitor` 等符号），需用 `pywin32` 的 `win32gui.EnumWindows` 或 ctypes 自行枚举。
- 「范围选择」按钮：在预览图上进入可拖拽编辑态（鼠标事件画矩形，画完回写到配置）。裁剪框以被捕获目标的**原始像素坐标**存储，显示时按预览缩放比例换算。
- 裁剪只在 web 输出前做：`frame.crop(x1, y1, x2, y2)` 只作用于推给 web 的那份数据。

**验收**：选窗口后预览切到该窗口；拖动范围框后 web 端画面被裁到框内，而磁盘上的 jpeg 仍是全尺寸。

### P4 Web 服务与 WebSocket

- 方案：Flask + Flask-SocketIO，`async_mode="threading"`，服务跑在后台线程，与 Qt 主线程共存。
- 起服务的方式（实测定稿）：**不用** `socketio.run()`（它不返回服务器对象，端口一改就没法优雅关掉），
  改用 `werkzeug.serving.make_server(...)` + 自己的线程，拿到 server 才能 `shutdown()`；
  `socketio.run()` 还要 `allow_unsafe_werkzeug=True` 才肯起，这套组合不需要。
  本机 `simple-websocket` 已随 python-engineio 装好，实测**真 WebSocket 升级是通的**
  （python-socketio 客户端报 `transport=websocket`），不需要 gevent/eventlet。
- 端口：默认 9178；校验 1024–65535；**改端口必须停旧服务再起新服务**（SocketIO 不支持热改端口）。
  端口占用要**显式探测**：Windows 上 `SO_REUSEADDR`（Python `HTTPServer` 默认开）允许两个进程
  绑同一端口，直接 `make_server` 不报错，会变成两个服务器抢连接。
- 路由：`/`（页面）、`/api/status`、`/api/latest`、`/api/list`、`/api/config`、
  `/cache/<name>`（原图）、`/web/latest.jpeg`（裁剪后的实时视图）、`/web/view/<name>`（历史图按需裁剪）、
  `/api/download/latest` 与 `/api/download/<name>`（附件下载）、`/api/pin|unpin/<name>`。
  取图一律先在 `store.list()` 里比对文件名，防路径穿越。
- 推送协议：`init`（连接即同步历史+状态）、`frame`（新截图）、`removed`（轮转删除）、
  `pinned`、`status`、`updated`（范围框改动）——前端只认这一份约定。
- 捕获回调**绝不**在 web 侧干活：总线事件只投进容量 1 的队列，由 web 自己的线程去裁剪+推送。

**验收**：捕获运行中 `curl http://127.0.0.1:9178/api/list` 返回递增的图片列表；浏览器控制台能看到持续到达的 `frame` 事件；改端口后新端口可用、旧端口已释放。
对应进度条目：1.2 端口相关项 + 1.3 的推送项。

### P5 Web 前端

- **`SPECPATH` 已经是 spec 所在目录**，`Path(SPECPATH).parent` 会指到项目外，

- **Flask-SocketIO 的 async 驱动要手动 hiddenimport**：engineio 在运行时按名字挑驱动
  （这里要 `engineio.async_drivers.threading`），静态分析看不见；漏了 web 服务起不来，

- **`--noconsole` 下 `sys.stdout` 是 None**：`logging_setup` 原来无条件建
  `StreamHandler(sys.stdout)`，打包后每条日志都会触发一次「Logging error」。改成
  `sys.stdout is not None` 才加控制台 handler，文件日志照旧。
- **`copy_metadata("windows-capture")`**：不拷发行版元数据，自检里的版本号会变成「未知版本」。
- **`web/static` 与 `templates` 必须 `--add-data`**；socket.io 客户端是本地文件，
  没有 CDN 兜底，漏了页面能打开但实时画面永远不动。
- **体积**：cv2 的 ffmpeg 视频插件（29 MB）、`opengl32sw.dll`（20 MB）、Qt 的
  `translations/*.qm`（96 个）与未用到的 Qt DLL 都可以剪；`cv2.pyd` 83 MB 剪不掉——
  `windows_capture` 的 `__init__` 里直接 `import cv2`。
- 验证必须**拷到项目外的干净目录**跑，否则「路径落在 exe 同级」这条根本测不出来。

## 五、主要技术决策

| 决策 | 选择 | 理由 |
| --- | --- | --- |
| 捕获方式 | `windows-capture`（Windows Graphics Capture） | 计划指定；可同时覆盖显示器与窗口，无需 DXGI 手写代码 |
| 窗口/显示器枚举 | pywin32 + `EnumDisplayMonitors` | 捕获库不含枚举 API，已核实；索引顺序必须跟捕获库一致 |
| 并发模型 | 单进程：捕获回调线程 + Qt 主线程 + Web 线程 | 避免引入多进程带来的缓存一致性问题 |
| Web 层 | Flask-SocketIO（threading 模式） | 计划指定；Windows 上避开 eventlet/gevent 的兼容坑 |
| 前端 | 原生 HTML/CSS/JS，无框架 | 计划指定；页面复杂度低 |
| 缓存 | 磁盘 jpeg，目录即真相 | 桌面端、web 端、下载按钮共用一套文件 |
| 裁剪位置 | 只在输出到 web 前裁 | 计划明确要求原图全尺寸保留 |
| 静止画面 | WGC 实时流 + GDI 心跳兜底 | WGC 是变化驱动，静止时一帧都不出；不兜底则缓存不轮转、预览/web 历史停摆 |
| 跨线程 | 总线事件 → `EngineBridge` 的 Qt 信号 | Qt 信号跨线程自动排队，捕获回调绝不直接碰控件 |
| 显示器索引 | 以 `EnumDisplayMonitors` 顺序为准 | 实测它与捕获库一致，Qt 的 screens() 顺序会把主显示器排前 |
| web 服务器 | `werkzeug.make_server` + 自建线程 | `socketio.run()` 不返回服务器对象，改端口就没法优雅关掉 |
| 实时传输 | Socket.IO（实测走 WebSocket 升级） | simple-websocket 随 engineio 自带，Werkzeug 下升级是通的 |
| 裁剪产物 | 实时走预生成的 `cache/web/latest.jpeg`，历史按需现裁 | 实时路径零延迟、不重复占盘；历史图点开才需要 |
| 删除同步 | 新增 `shot.removed` → 前端 `removed` 事件 | 否则轮转后缩略图 404 变破图 |
| 托盘图标 | `QPainter` 自绘两套（捕获中/已停止） | 不引外部图片资源，打包后也在 |

## 六、风险与备选

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 捕获目标为管理员权限窗口 | 画面黑屏/失败 | 以管理员身份运行本程序；或提示用户 |
| 窗口标题重复 | 选中错误窗口 | 一律用 hwnd 定位，标题只用于展示 |
| 回调缓冲区被复用 | 图片撕裂/半张图 | 回调内完成编码或深拷贝（见 P1） |
| `windows-capture` 后续版本移除/改名 API | 代码失效 | 用一层 `core/capture.py` 隔离，接口只暴露 start/stop/switch |
| 端口被占用 | web 起不来 | 启动前探测 + 失败提示，不静默吞掉异常 |
| 打包体积与启动时间 | 体验差 | onedir + exclude 未用 Qt 模块；必要时放弃 onefile |
| 打包后 `web/static`、`templates` 漏进包 | 页面能开、实时画面永远不动 | `--add-data` 显式加入，并用浏览器实测 Socket.IO 是否真的连上 |
| 打包后 engineio 找不到 async 驱动 | web 服务起不来，报错很间接 | hiddenimport `engineio.async_drivers.threading` 等；浏览器连上看 `conn=已连接` |
| `--noconsole` 下 `sys.stdout` 为 None | 每条日志触发「Logging error」 | 只在 `sys.stdout is not None` 时加控制台 handler，文件日志照旧 |
| 多屏 DPI 缩放 | 裁剪坐标错位 | 坐标统一以原始像素为基准，显示层做纯换算，不反向推导 |
| 静止画面没有帧 | 历史不再增长、预览停更 | 已实现静止兜底心跳（`capture.heartbeat_fallback`），GDI 按需抓帧 |
| Qt 与捕获库的显示器顺序不一致 | 选错屏 | 屏幕选择栏改用 `EnumDisplayMonitors` 顺序，并用两条通路的画面比对验证（平均像素差 0.03） |
| GDI 兜底图的上下方向 | 画面倒置 | `GetBitmapBits` 已是自上而下，**不要** `flipud`（用不对称测试窗口验证） |
| Windows 下 `SO_REUSEADDR` 允许重复绑定 | 两个服务器抢同一端口、静默双绑定 | 启动前用 `connect_ex` 显式探测端口占用，占用则返回失败并说明端口号 |
| 前端状态被部分响应冲成空值 | 状态区显示「—」，误以为捕获没跑 | `/api/latest` 返回完整状态；前端 `applyStatus` 只做字段合并 |
| 缓存轮转删了文件，前端还挂着旧缩略图 | 缩略图 404 变破图、钉住静默失败 | 新增 `shot.removed` → `removed` 事件；缩略图 `onerror` 自摘；钉住用 ack 回报真实结果 |
| Python 版 Socket.IO 测试客户端缺依赖 | 连接报「Unexpected connection error」 | `requirements-dev.txt` 里装 `requests`（轮询）与 `websocket-client`（WS 升级） |
