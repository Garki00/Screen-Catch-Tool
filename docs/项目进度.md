**P1 静止兜底与「按间隔落盘」（实测）**

WGC 只在画面变化时出帧，完全静止的窗口 15 秒只落盘 1 张 → 引擎内加静止心跳：
窗口用 `PrintWindow(PW_RENDERFULLCONTENT)`、显示器用 `CreateDC("DISPLAY")` + `BitBlt`
按需抓一帧（配置项 `capture.heartbeat_fallback`）。

```bat
.venv\Scripts\python.exe tests\test_fallback.py
```

结果：17/17。静止窗口 5 张，间隔 **2.02 / 2.05 / 2.04 / 2.03 秒**（目标 2 秒）；
显示器捕获 14 秒 / 间隔 2 秒 → 落盘 **7 张**（14/2 = 7，不多不少），`verify_shots.py` 全项通过。

途中修掉的坑：心跳判据里原本有「距上次收到帧不足一个间隔就跳过」，画面轻微活动时 WGC 出帧
频率远高于落盘间隔，心跳被无限推迟，实测间隔漂到 **4.03s / 2.56s**。改成**只按「距上次落盘」**
判断，并把「一个间隔最多一张」做成 `_save_image` 里 `_save_lock` 内的**原子占位**
（WGC 回调与心跳线程同时越过间隔门也只存一张）。

**显示器索引映射（实测）**

## 备注

- 计划写的是 Python 3.11+，本机实际用 3.13.9（`windows-capture` 的 wheel 是 `cp39-abi3`，3.9+ 通用）。
- 已安装并验证可导入：numpy 2.5.3、opencv-python 5.0.0.93、windows-capture 2.0.1、
  PySide6 6.11.2、Flask 3.1.3、Flask-SocketIO 5.6.1、Pillow 12.3.0、pywin32 312、
  pyinstaller 6.22.3；测试另装 requests 2.34.2、websocket-client 1.9.2。
- **本机显示器与索引（实测，与 Qt 的顺序不同）**：
  - `monitor_index=1` = `B156HAN15.H`，物理 1920x1080，125% 缩放，矩形 (1920, 92, 3840, 1172)
  - `monitor_index=2` = `P24A2G`，1920x1080，100%，矩形 (0, 0, 1920, 1080)，**主显示器**
  - 索引顺序以 `EnumDisplayMonitors` 为准；Qt 的 `QGuiApplication.screens()` 把主显示器排在第一位，
    两者**不一致**，所以「屏幕选择栏」不能直接用 Qt 的顺序（`window_list.list_monitors` 已按其修正）。
  - 125% 缩放屏上抓到的仍是物理像素（1920x1080），范围框坐标一律以物理像素为基准。
- `config/settings.json` 的 `capture.target.monitor_index` 从 **1** 开始计数（0 会被捕获库拒绝）；
  旧配置里的 0 会在读取时自动纠正并回写。
- 配置项：`capture.preview_enabled` / `preview_interval_ms`（400）/ `preview_max_width`（960）/
  `heartbeat_fallback`（true）/ `server.host`（默认 `127.0.0.1`，改成 `0.0.0.0` 才能用手机访问）。
- web 端的实时通信确实是 **WebSocket**（Socket.IO 升级成功，实测传输名为 `websocket`），
  不是降级轮询；服务端用 `werkzeug.serving.make_server` 自建线程，为的是能优雅重启端口。
- `cache/web/latest.jpeg` 是给 web 端看的裁剪视图（`cache/screenshots/` 里的原图永远不裁）；
  历史图点开时走 `/web/view/<name>` 现裁，不额外占磁盘。
